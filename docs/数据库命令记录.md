# 数据库命令记录

服务端使用 SQLite（better-sqlite3）。数据库文件路径由环境变量 `DB_PATH` 决定，默认为服务启动目录下的 `./data/app.db`。
```bash
cd /var/www/english-study-server/apps/server
```

以下命令默认在服务运行目录下执行。

## 账号与权限

### 查看所有账号

```bash
sqlite3 data/app.db "SELECT id, username, role FROM users;"
```

### 将账号设为管理员

`users` 表的 `role` 字段控制权限，默认 `'user'`，管理员为 `'admin'`。

```bash
sqlite3 data/app.db "UPDATE users SET role='admin' WHERE username='用户名';"
```

说明：

- 不用重启服务、也不用重新登录：每次请求都会用 token 联表查询 `users.role`，改完立即生效。
- 前端如果缓存了登录时返回的 `role`，界面上的管理员入口可能要重新登录才显示。

### 没有 sqlite3 命令行时的替代写法

```bash
node -e "const db=require('better-sqlite3')('data/app.db');db.prepare(\"UPDATE users SET role='admin' WHERE username=?\").run('用户名')"
```

## 口语评测配额（speech_attempts）

跟读评分每下发一次评测地址就在这张表登记一条，兼作配额账本和录音去重。要点：

- **只记次数和指纹，不存音频、不存分数**。分数在前端进度里，随 `/api/progress` 同步
- `quota_day` 是**北京时间的日期**（不是 UTC），当天计数就靠它
- 同一账号同一天内「同一次提交（`attempt_id`）」或「同一段音频（`audio_hash`）」只算一次；跨天允许重评同一段录音

```bash
# 某账号今天已经用掉多少次（对照 config.ts 的 perAccountPerDay=300）
sqlite3 data/app.db "SELECT COUNT(*) FROM speech_attempts WHERE user_id=1 AND quota_day='2026-09-30';"

# 某个词今天的次数（对照 perWordPerDay=10）
sqlite3 data/app.db "SELECT COUNT(*) FROM speech_attempts WHERE user_id=1 AND quota_day='2026-09-30' AND word_id='g7a-u0-w1';"

# 看某用户最近的评分记录
sqlite3 data/app.db "SELECT word_id, attempt_id, quota_day, created_at FROM speech_attempts WHERE user_id=1 ORDER BY id DESC LIMIT 10;"
```

排查"用户说评不了分"时的顺序：先确认 `quota_day` 用的是当天北京日期，再看该账号当日计数是否到 300、该词是否到 10、是不是当天已经提交过这段录音（重复会返回 409）。

表会一直增长（每账号每天最多 300 行），目前不需要清理；真要清历史可以：

```bash
sqlite3 data/app.db "DELETE FROM speech_attempts WHERE quota_day < '2026-09-01';"
```
