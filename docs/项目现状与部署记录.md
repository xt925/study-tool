# 项目现状与部署记录

> 最后更新：2026-10-11。本文记录当前项目的整体结构和线上部署情况，方便换电脑/隔段时间后快速回忆。

## 项目是干什么的

给初中生（外甥）用的英语单词学习 H5 + Android APK：

- 词库按册划分：七上 / 七下 / 八上 / 八下 / 九上 / 九下，每册按 Unit 细分，支持单词和词组（多词性、多义项）
- 玩法：学词、测验（看英选义/拼写等模板题）、小游戏（配对连线、听音选词、对战 KO、打字过河）、复习、错题本
- 激励：星星 / 等级、连续打卡、成就徽章
- 家长端：家长中心可看学习汇总和近 7 天周报，给孩子设每日目标与寄语（孩子首页可见）
- 跟读打分**不是独立游戏入口**，已并入「开始学习」：学词时录音 → 存到浏览器本地 → 用户主动点「评分这段录音」
- 单词发音用 edge-tts 预生成 mp3（音频不进 git，按词库哈希缓存）
- 账号体系：普通账号（学生）+ 唯一 admin（家长），家长中心可看所有用户的学习汇总
- 进度本地存储（localStorage)，登录后自动同步到服务器（改动后 3 秒防抖即传 + 5 分钟兜底 + 启动/登录/回到前台时各同步一次）

## 仓库结构（monorepo,npm workspaces)

```
apps/h5        Vue3.5 + Vite6 + Tailwind + Pinia，线上 base 为 /english-study/
apps/uni       HBuilderX 可视化项目，webview 壳指向线上 H5（绝不要装 node_modules）
               只在冷启动带 ?launch=时间戳 防 index.html 吃缓存；回到前台**不重载**
               （重载会把人从当前单元踢回首页、丢掉学习进度），回前台的数据刷新由 H5 自己的
               visibilitychange 监听负责
apps/server    Fastify + better-sqlite3，账号/进度同步/家长汇总接口
packages/core  @study/core 纯 TS 包：词库数据(words_7a~9b.ts)、进度 store、测验逻辑
scripts/       parse_words.py(词表转 TS)、generate_audio.py(生成音频)
docs/          音标字符表、词表解析脚本指南、数据库命令记录、跟读打分对接与密钥配置、本文
```

## 服务器部署情况（阿里云）

- 服务器 Node 统一用 **v22**(pm2 服务、node_modules 原生模块都绑这个版本）。曾出现 nvm 默认装 Node 24 抢占 PATH 导致 better-sqlite3 版本错报的坑；如需切换先确认 `node -v` 是 22，否则原生模块要重装
- **H5 静态文件**:`/var/www/html/english-study/`
- **服务端代码**:`/var/www/english-study-server/`(apps/server + packages/core 的精简 monorepo,npm install --omit=dev)
- **数据库**:`/var/www/english-study-server/apps/server/data/app.db`(SQLite，部署不会覆盖它）
- **进程管理**:pm2，进程名 `english-study-server`，开机自启已配置
- **nginx 要点**:
  - `location /english-study/` 静态托管，SPA fallback 到 index.html
  - `index.html` 加 `Cache-Control: no-cache`（发版后 WebView 立刻更新）
  - `/assets/` 的 js/css 长缓存 immutable（文件名带哈希）
  - `/audio/` 的 mp3 缓存 1 天（替换发音后最长 1 天生效，过期只是 304 比对，不无脑重下）
  - `location /english-study/api/` → `proxy_pass http://127.0.0.1:3000/api/`,**必须配在 443 的 server 块里**

## CI/CD(.github/workflows/deploy.yml)

- 触发方式：打 tag(`v*`）或 Actions 页面手动 workflow_dispatch
- H5 构建含 edge-tts 音频生成，**音频缓存按 ref 隔离**:main 上手动触发才能逐次增量；tag 发布只能基于 main 的最新缓存（tag 自己的缓存下一个 tag 读不到）。加了很多新词后，先在 main 手动跑一次再打 tag
- 服务端部署按"与上一个 tag 的文件差异"判断（apps/server、packages/core、package-lock.json 变更才部署；手动触发总是部署）
- 部署密钥：仓库 secrets(SERVER_HOST / SERVER_USER / SERVER_SSH_KEY)，本地私钥 deploy_key 已加入 .gitignore

## 服务端账号管理

所有 seed 命令都要在**仓库根目录**跑。（`--workspace` 是 npm workspaces 的参数，只在声明了 `workspaces` 的根 `package.json` 那层生效；在 `apps/server` 里跑会报 `No workspaces found`。）

```bash
# 创建/重置普通账号
npm run seed --workspace apps/server -- --user 用户名 --pass 密码 --role user

# 重置 admin 密码（忘了密码就用这条；本地照样能在根目录跑，DB 是本地那个）
npm run seed --workspace apps/server -- --user admin --pass 新密码 --role admin

# 首次初始化 admin
ADMIN_PASS=你的密码 npm run seed --workspace apps/server
```

几个坑：

- **重置 admin 时 `--role admin` 不能省**。脚本是 upsert，会把 role 一起覆盖，不带这个参数 admin 会被降级成普通 user，家长中心就进不去了。
- `ADMIN_PASS` **只在 admin 不存在时生效**。admin 已存在时会直接打印「admin 账号已存在，跳过」，改不了密码——所以拿它来"找回密码"是没用的，要用上面那条 `--user admin`。
- DB 路径是相对当前工作目录的（`./data/app.db`）。别在根目录直接跑 `npx tsx apps/server/scripts/seed.ts ...`，那会在根目录生成一个全新的空库，跟真正在用的不是一个。
- 改完账号/密码后要**重启服务端**（线上 `pm2 restart english-study-server`，本地重启 `dev:server`），否则运行中的进程可能还连着旧 DB 的文件句柄。

## 学习功能与进度数据（2026-10 新增）

复习、错题本、连续打卡、成就四个功能的数据都在进度 JSON 里，随 `/api/progress` 一起同步。
服务端 `normalizeProgress` 已同步补齐这些字段，**漏了会被丢弃**，以后加字段记得两边都改。

### 复习（间隔重复）
- 数据：`reviewStates: Record<wordId, { wordId, stage, dueAt, lastReviewedAt }>`
- 间隔：`[1,2,4,7,15,30,60]` 天。答对 stage+1、拉长间隔；答错回到 stage 0 并在 10 分钟后重现
- 学新词自动入队（1 天后首次复习）
- 存量迁移：已学但没有复习记录的词按「每天 20 个」摊到未来几天，避免老用户一上来就面对上百个待复习
- 入口：首页「🔁 复习」（`ReviewView.vue`），单次最多 20 个（`SESSION_SIZE`）
- 跨设备合并：同一个词取 `lastReviewedAt` 更新的一条

### 错题本
- 数据：`wrongWords: Record<wordId, { wordId, count, lastWrongAt }>`，上限 200，超出淘汰最早答错的
- 判错接入：测验（QuizView）、听音选词（ListenGame）、打怪（BattleGame）、单词配对（MatchGame）
- **打字过河（TypingGame）有意不接入**：打字速度游戏，误触键盘不算单词记错
- 只有「错题本重练答对」才移除（`clearWrongWord`，+5⭐）；在别处偶然答对不会清账
- 入口：首页「📕 错题本」（`WrongBookView.vue`）

### 连续打卡
- 数据：`streak` / `maxStreak` / `lastActiveDate`
- 触发：`addStars` / `markWordLearned` / `markReviewed` 都会调 `touchStreak()`，同一天只算一次；断签后从 1 重新开始
- 展示用 getter `currentStreak`：超过一天没学显示 0
- 老数据迁移：用 `dailyWords` 反推连续/最长记录。**历史上只玩游戏、没学新词的日子不会被计入**（当时没留下按天数据，补不回来）

### 成就 / 徽章
- 数据：`achievements: Record<achievementId, unlockedAt>`
- 定义在 `packages/core/src/utils/achievements.ts`，共 17 枚，按词汇量 / 星星 / 单元 / 打卡 / 复习掌握 / 跟读分档
- 每次 `persist()` 自动调 `evaluateAchievements()`；老数据在 `loadState` 里 `backfillAchievements` 静默补齐
- 入口：首页左上角 🏆（`AchievementsView.vue`）；解锁时 App.vue 顶部弹轻提示（同时解锁多个只弹最后一个）
- 「复习掌握」的口径：`reviewStates` 里 `stage >= 3`（`MASTERED_STAGE`）

### 家长端闭环
- 新表 `parent_notes`（`user_id` / `daily_goal` / `message` / `updated_at`），服务启动时 `CREATE TABLE IF NOT EXISTS` 自动建，部署无需手动迁移
- `GET /api/parent-note`：孩子读取自己的目标/寄语
- `PUT /api/admin/parent-note/:username`：admin 给孩子设置（目标 0~200、寄语≤100 字；拒绝给 admin 账号设置）
- 家长中心（AdminView）：每个孩子可设「每日目标 + 鼓励寄语」，显示今日进度 / 连续天数 / 是否达标，并可展开「近 7 天报告」
- 孩子首页（HomeView）：登录后展示「👪 家长寄语」+ 今日目标进度条，达标提示
- `GET /api/admin/summary` 扩展字段：`role` / `todayWords` / `streak` / `maxStreak` / `dailyGoal` / `message` / `week`
- 周报 `week`：最近 7 天（含今天，**不是自然周**）的每日词数、总词数、活跃天数、复习词数、跟读次数、达标天数
- 时区：服务端「今日 / 近 7 天」按北京时间日（`quotaDay()`）；孩子端按设备本地日期

### 已知取舍
- 家长寄语在首页挂载时拉取，家长改了以后孩子需重新进首页才刷新
- 周报「复习词数」是这 7 天复习过的单词数（按每个词最近一次复习时间），不是复习总次数
- 成就解锁提示同时解锁多个时只弹最后一个（成就页都能看到）

## 口语评测（腾讯云智聆 SOE）配置

跟读评分集成在开始学习的单词录音中，录音保存后由用户主动选择评分，使用腾讯云智聆口语评测（新版）。服务端限额集中配置在 `apps/server/src/config.ts`（每词每日 10 次、每账号每日 300 次）。
**完整对接说明、拿密钥步骤、排错表见 [跟读打分对接与密钥配置.md](跟读打分对接与密钥配置.md)**，这里只留要点：

- 服务端环境变量：`SOE_APP_ID` / `SOE_SECRET_ID` / `SOE_SECRET_KEY`（必填）+ `SOE_SCORE_COEFF`（可选，默认 1.5，越大打分越严）
- 本地放 `apps/server/.env`（已 gitignore）；线上放服务器同路径，然后 `pm2 restart english-study-server`
- 设计：SecretKey 只在服务端，`/api/speech/token` 签名后只把短时效 WSS 地址给前端，音频前端直连腾讯
- 接口需登录；一个单词/一句话算 1 次调用，扣腾讯云套餐包
- **配额日按北京时间零点切分**（`config.ts` 里的 `quotaDay()`，不是 UTC——UTC 日在北京时间上午 8 点前还停在昨天）
- 同一账号在**同一个配额日内**，「同一次提交」或「同一段录音」只计一次；**跨天后允许用同一段录音重新评分**（避免一次瞬时网络失败就把录音永久作废）
- **下发签名地址就扣次数（预扣）**：音频直连腾讯、服务端看不到评测结果，所以评测成败都扣。这是为了不让配额形同虚设的有意取舍，不是 bug
- 评分记录存在前端进度里（`speechScores`），随 `/api/progress` 一起同步；本地只保留最近 500 条，避免长期使用后无限膨胀

## 已知注意事项

- 进度是整包 JSON 存进 `progress.data` 的，**服务端没做体积/条数校验**（前端会裁剪：跟读评分记录保留最近 500 条、错题本保留最近 200 条）。正常客户端不会超，暂不加限制——万一以后有人手搓请求塞超大数组，得在这层补校验
- PowerShell 里跑 npm 带参数容易丢参数，本地操作建议用 Git Bash
- parse_words.py 输出必须用 `-o` 指定文件，不要用 `>` 重定向（Windows 下会乱码）
- 服务器上 GitHub/raw.githubusercontent.com 基本不可达，装东西一律走国内镜像（npmmirror / gitee)
