# 项目现状与部署记录

> 最后更新：2026-09-29。本文记录当前项目的整体结构和线上部署情况，方便换电脑/隔段时间后快速回忆。

## 项目是干什么的

给初中生（外甥）用的英语单词学习 H5 + Android APK：

- 词库按册划分：七上 / 七下 / 八上 / 八下 / 九上 / 九下，每册按 Unit 细分，支持单词和词组（多词性、多义项）
- 玩法：学词、测验（看英选义/拼写等模板题）、小游戏（配对连线、听音选词、对战 KO、跟读打分）
- 单词发音用 edge-tts 预生成 mp3（音频不进 git，按词库哈希缓存）
- 账号体系：普通账号（学生）+ 唯一 admin（家长），家长中心可看所有用户的学习汇总
- 进度本地存储（localStorage)，登录后自动同步到服务器（改动后 3 秒防抖即传 + 5 分钟兜底 + 启动/登录时各同步一次）

## 仓库结构（monorepo,npm workspaces)

```
apps/h5        Vue3.5 + Vite6 + Tailwind + Pinia，线上 base 为 /english-study/
apps/uni       HBuilderX 可视化项目，webview 壳指向线上 H5（绝不要装 node_modules）
apps/server    Fastify + better-sqlite3，账号/进度同步/家长汇总接口
packages/core  @study/core 纯 TS 包：词库数据(words_7a~9b.ts)、进度 store、测验逻辑
scripts/       parse_words.py(词表转 TS)、generate_audio.py(生成音频)
docs/          音标字符表、词表解析脚本指南、本文
```

## 服务器部署情况（阿里云）

- 服务器 Node 统一用 **v22**(pm2 服务、node_modules 原生模块都绑这个版本）。曾出现 nvm 默认装 Node 24 抢占 PATH 导致 better-sqlite3 版本错报的坑；如需切换先确认 `node -v` 是 22，否则原生模块要重装
- **H5 静态文件**:`/var/www/html/english-study/`
- **服务端代码**:`/var/www/english-study-server/`(apps/server + packages/core 的精简 monorepo,npm install --omit=dev)
- **数据库**:`/var/www/english-study-server/apps/server/data/app.db`(SQLite，部署不会覆盖它）
- **进程管理**:pm2，进程名 `english-study-server`，开机自启已配置
- **nginx 要点**:
  - `location /english-study/` 静态托管，SPA fallback 到 index.html
  - `index.html` 加 `Cache-Control: no-cache`（发版后 WebView 立刻更新）
  - `/assets/` 的 js/css 长缓存 immutable（文件名带哈希）
  - `/audio/` 的 mp3 缓存 1 天（替换发音后最长 1 天生效，过期只是 304 比对，不无脑重下）
  - `location /english-study/api/` → `proxy_pass http://127.0.0.1:3000/api/`,**必须配在 443 的 server 块里**

## CI/CD(.github/workflows/deploy.yml)

- 触发方式：打 tag(`v*`）或 Actions 页面手动 workflow_dispatch
- H5 构建含 edge-tts 音频生成，**音频缓存按 ref 隔离**:main 上手动触发才能逐次增量；tag 发布只能基于 main 的最新缓存（tag 自己的缓存下一个 tag 读不到）。加了很多新词后，先在 main 手动跑一次再打 tag
- 服务端部署按"与上一个 tag 的文件差异"判断（apps/server、packages/core、package-lock.json 变更才部署；手动触发总是部署）
- 部署密钥：仓库 secrets(SERVER_HOST / SERVER_USER / SERVER_SSH_KEY)，本地私钥 deploy_key 已加入 .gitignore

## 服务端账号管理

所有 seed 命令都要在**仓库根目录**跑。（`--workspace` 是 npm workspaces 的参数，只在声明了 `workspaces` 的根 `package.json` 那层生效；在 `apps/server` 里跑会报 `No workspaces found`。）

```bash
# 创建/重置普通账号
npm run seed --workspace apps/server -- --user 用户名 --pass 密码 --role user

# 重置 admin 密码（忘了密码就用这条；本地照样能在根目录跑，DB 是本地那个）
npm run seed --workspace apps/server -- --user admin --pass 新密码 --role admin

# 首次初始化 admin
ADMIN_PASS=你的密码 npm run seed --workspace apps/server
```

几个坑：

- **重置 admin 时 `--role admin` 不能省**。脚本是 upsert，会把 role 一起覆盖，不带这个参数 admin 会被降级成普通 user，家长中心就进不去了。
- `ADMIN_PASS` **只在 admin 不存在时生效**。admin 已存在时会直接打印「admin 账号已存在，跳过」，改不了密码——所以拿它来"找回密码"是没用的，要用上面那条 `--user admin`。
- DB 路径是相对当前工作目录的（`./data/app.db`）。别在根目录直接跑 `npx tsx apps/server/scripts/seed.ts ...`，那会在根目录生成一个全新的空库，跟真正在用的不是一个。
- 改完账号/密码后要**重启服务端**（线上 `pm2 restart english-study-server`，本地重启 `dev:server`），否则运行中的进程可能还连着旧 DB 的文件句柄。

## 口语评测（腾讯云智聆 SOE）配置

跟读打分（游戏乐园 → 🎤 跟读打分）用腾讯云智聆口语评测（新版）。
**完整对接说明、拿密钥步骤、排错表见 [跟读打分对接与密钥配置.md](跟读打分对接与密钥配置.md)**，这里只留要点：

- 服务端环境变量：`SOE_APP_ID` / `SOE_SECRET_ID` / `SOE_SECRET_KEY`（必填）+ `SOE_SCORE_COEFF`（可选，默认 1.5，越大打分越严）
- 本地放 `apps/server/.env`（已 gitignore）；线上放服务器同路径，然后 `pm2 restart english-study-server`
- 设计：SecretKey 只在服务端，`/api/speech/token` 签名后只把短时效 WSS 地址给前端，音频前端直连腾讯
- 接口需登录；一个单词/一句话算 1 次调用，扣腾讯云套餐包

## 已知注意事项

- PowerShell 里跑 npm 带参数容易丢参数，本地操作建议用 Git Bash
- parse_words.py 输出必须用 `-o` 指定文件，不要用 `>` 重定向（Windows 下会乱码）
- 服务器上 GitHub/raw.githubusercontent.com 基本不可达，装东西一律走国内镜像（npmmirror / gitee)
