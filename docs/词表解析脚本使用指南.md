# 词表解析脚本使用指南

脚本位置：`scripts/parse_words.py`，作用是把微信识图复制出来的课本词表，快速转换成 `packages/core/src/data/words.ts` 需要的 TS 数据格式。

## 输入文件格式要求

每行一条，两种形式：

```
单词 /音标/ 词性.释义 [词性.释义 ...]
词组 词组意思
```

示例：

```
suppose /sa'pauz/ v.想,认为
doubt /daut/ n.不确定，怀疑 v.怀疑，不相信，不信任
instead of 代替......;而不是......
```

注意事项：

- 同一个单词只占一行
- 词性和释义之间必须有 `.`（如 `n.苹果`），脚本靠这个点识别词性
  - 例外：整个词条都没有词性也可以（如 `am /ei'em/ 午前,上午`），会解析为无词性词条
- 一个词有多个词性时，按 `n.释义 v.释义` 的顺序写在同一行，用空格隔开
- 没有 `/音标/` 的行会被当作词组（纯英文部分 + 中文意思），词组中允许括号（如 `lend(sb) a hand 帮助(某人)做事`）

## id 前缀对照表

`--id-prefix` 参数 = 册 + 单元，规则如下：

| 课本 | 册前缀 | Unit 1 | Unit 2 | Unit 3 |
| ---- | ------ | ------ | ------ | ------ |
| 七年级上册 | g7a | g7a-u1 | g7a-u2 | g7a-u3 |
| 七年级下册 | g7b | g7b-u1 | g7b-u2 | g7b-u3 |
| 八年级上册 | g8a | g8a-u1 | g8a-u2 | g8a-u3 |
| 八年级下册 | g8b | g8b-u1 | g8b-u2 | g8b-u3 |
| 九年级上册 | g9a | g9a-u1 | g9a-u2 | g9a-u3 |
| 九年级下册 | g9b | g9b-u1 | g9b-u2 | g9b-u3 |

脚本会按前缀自动编号：`g8b-u3-w1`、`g8b-u3-w2`……

## 完整操作流程

以"八年级下册 Unit 3"为例：

```bash
# 1. 把识图复制的词表存成文本文件，放 scripts/ 下，命名随意
#    scripts/八年级下册unit3

# 2. 解析（-o 直接写文件，固定 UTF-8，比 > 重定向可靠）
python scripts/parse_words.py scripts/八年级下册unit3 --id-prefix g8b-u3 -o scripts/.out-u3.ts

# 3. 检查输出：解析失败/可疑的行会列出行号和原文

# 4. 打开 scripts/.out-u3.ts，把内容粘贴进
#    packages/core/src/data/words.ts 里 grade8b 的 units 数组中，包成：
#
#    {
#      id: 'grade8b-unit3',
#      title: 'Unit 3',
#      words: [
#        ...粘贴的内容...
#      ],
#    },

# 5. 生成音频（只生成新增词条的音频，已有的自动跳过）
npm run gen:audio
```

⚠️ **不要用 PowerShell 的 `>` 重定向输出**：PowerShell 会对输出二次转码（把 UTF-8 字节按 GBK 解码再存成 UTF-16LE），导致文件乱码。要么用 `-o` 参数，要么在 Git Bash 里用 `>`。

第 4 步手动粘贴容易出错，也可以直接把词表文件交给 AI（"这是八下 unit3"）自动完成解析和接入。

## 脚本的自动清洗行为

- 去掉释义末尾粘上的纯数字（识图常把页码粘进来，如 `有风险的12` → `有危险的，有风险的`）
  - 想去掉这个行为：删除 `clean_meaning` 里的 `re.sub(r'\d+$', '', s)` 一行
- 去掉词性后多余的点（如 `n........巷` → 释义从"巷"开始）

## 解析失败常见原因

| 现象 | 原因 |
| ---- | ---- |
| 整行解析失败 | 词性后的 `.` 丢了（识图漏识别） |
| 词性被归错 | 词性拼写不在识别表里（脚本支持 n/v/vt/vi/adj/adv/prep/conj/pron/num/det/art/interj/aux/abbr/modal 等 20 种） |
| 词组没识别 | 英文部分和中文意思之间没有空格 |
